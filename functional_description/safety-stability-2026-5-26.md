# Harness-Lite 核心系统架构重构与安全稳定性升级报告

本报告详尽记录了针对 `Harness-Lite` 智能体（AI Agent）核心编排框架进行的全方位、生产级架构重构。本次重构深度对齐了先进 Agent（如 Claude Code）的设计哲学，彻底解决了原版框架在多用户高并发场景下的**沙箱逃逸漏洞、会话串号越权、上下文 Token 膨胀、图形环境死锁**以及**非标准字符编码崩溃**等灾难性硬伤。

通过构建“立体防御、有状态隔离、自适应收缩、双轨记忆”的底层基础设施，重构后的 `Harness-Lite` 已具备工业级的超长航时逻辑续航与滴水不漏的安全边界。

## 模块一：立体纵深多层安全防御体系（精细化行为审计）

### 1. 核心痛点分析
原有的安全管理器采用“一刀切”的模块黑名单策略，一旦检测到代码中包含特定模块导入就会直接封杀。这极大地扼杀了 Agent 处理正当工程问题（如路径拼接或环境检查）的能力。同时，原有的静态正则拦截无法防范高明的 Shell 变形混淆（如 Base64 编码逃逸），且漏掉了对内容检索与目录列出工具的路径校验。

### 2. 升级架构设计
我们重构为**三层漏斗流式防御架构**，从“封杀模块”走向“行为审计”：
- **Layer 1：确定性静态防御层（AST 细粒度审计）**：利用 Python 官方抽象语法树分析器。**放行无害模块导入**，但精准拦截模块下的高危破坏性节点（如系统底层调用、常驻子命令开启、外部子进程派生等）。同时对所有涉及物理边界的工具进行强制的绝对路径锚定，锁死在专属沙箱内。
- **Layer 2：语义意图审查层（LLM Critic）**：针对终端和解释器等高动态工具，暗中拦截并交由专属安全小模型进行社会工程学意图推导，输出安全信任分。低于临界值直接熔断。
- **Layer 3：人工审查确认层（HITL 终审）**：当信任分处于灰色地带或涉及环境敏感变更（如依赖库安装）时，挂起异步循环，控制台高亮打印原始参数并提供人类用户交互反馈线。

## 模块二：多租户 Worker 进程池隔离与常驻终端自愈系统

### 1. 核心痛点分析
原有的常驻常活持久化终端驱动器是一个**全局单例**。在高并发场景下，所有的并发会话在共享同一个底层的终端进程和同一个输入输出缓冲区。这直接导致了灾难性的**会话串号越权、状态交叉污染**。且遇到命令卡死或超时时，原代码仅仅发送软中断信号，极易由于输入流未闭合而导致整个常驻通道缓冲区污染并永久卡死。

### 2. 升级架构设计
- **ContextVar 会话染色机制**：引入异步上下文追踪变量，在无需修改所有工具函数签名的前提下，在协程入口对当前工作线程进行会话生命周期染色。
- **多租户 Worker 进程池**：为每一个独立的会话标识动态分配、托管一个完全独占的常驻进程，彻底打碎并发竞态条件。
- **后置绝对路径刺探**：每次命令执行完，系统在底层自动尾随注入路径查询，刺探真实物理轨迹。一旦发现模型通过特殊命令跳转逃出沙箱，立刻抓现行强杀，并回滚环境。
- **强杀与状态重放自愈**：超时线一到，直接通过进程组发送强制断开信号，连同派生子命令一同击毙。随后自动拉起干净新进程，并根据快照自动重放最近一次验证安全的路径。
- **Linux 物理配额硬限制**：通过钩子注入系统级物理资源硬限制。硬性限制单个 Worker 的最大虚拟内存配额（防止内存溢出榨干宿主机）、最大允许派生子进程数（阻断进程炸弹）以及文件单次写入尺寸。

## 模块三：仿 Claude Code 双轨制分层记忆管理系统

### 1. 核心痛点分析
先进的 Agent 架构不应依赖沉重的外部向量数据库，也不应听任工具原始日志无限追加。原有的短期工作记忆随窗口截断而彻底消失，导致 Agent 无法跨会话进行“吃一堑长一智”的长期自我演进。

### 2. 升级架构设计
我们完美复刻了 Claude Code 的记忆哲学，采取**“左脑流水账，右脑备忘录”的双轨解耦制**：
- **左脑（短期工作历史 - JSON 存储层）**：完全遵循按天分卷存储的优良习惯，每天生成对应的日期目录，内部存放包含全量原子工具交互快照的流水日志，以此提供精准的原生接口线性承接契约。
- **右脑（长期经验记忆 - Markdown 存储层）**：在根目录开辟跨越天数、长效积累的固定项目区。包含存放静态技术栈规范与显式开发指南的项目说明书，以及智能体自主学习与动态纠错的长期自愈经验库。
- **自主记忆蒸馏引擎**：当且仅当发生人工终审被用户明确阻断拒绝、或长任务严重报错时精准触发。系统通过后台非阻塞的同步客户端调用，将复杂的长历史流水账，“高阶脱水”提炼总结为一行极其简炼的文本负向反馈指南（行为惩罚记忆），永久追加写入备忘录。新对话启动时，该内容会作为先验知识高亮注入到初始提示词中。

## 模块四：自适应 Token 压缩与内核状态硬锚定上下文管理器

### 1. 核心痛点分析
直接按条数截断容易触发大模型接口消息配对报错（孤立的工具返回消息缺失对应的思考催生消息）。更致命的是，一旦历史被大模型摘要压缩，大模型会遗忘早期的环境位移路线，导致在有状态终端内发生**“空间迷失幻觉”**。

### 2. 升级架构设计
我们建立了**全新上下文收缩管理器**：
- **精准 Token 监控**：引入分词编码器进行像素级 Token 盘点，将高水位红线设在模型的高效注意力智商区间（避免在超长窗口下推理失焦与延迟飙升）。
- **严格配对成批抽离**：采用严格的“批处理成对提取算法”。被抽离去压缩的工具结果消息，其对应的思考与工具调用请求消息必定会被同时摘除，完美捍卫大模型原生通信契约。
- **环境内核状态硬锚定（GPS 导航桩）**：历史可以被摘要和模糊化，但当前终端的工作目录属于物理内核状态。压缩器在生成历史摘要快照的同时，**动态刺探常驻终端的最新物理路径，作为“绝对真理”强行封装注入最新的系统检查点消息中**。大模型一抬头就能看见无可撼动的绝对坐标，使 Agent 在高压缩历史下也绝不迷路。

## 模块五：工业级 OpenAI SDK 全量重构与流式鲁棒性强化

### 1. 核心痛点分析
手写底层 HTTP 网络请求进行流式拼装过于脆弱，无法处理非标第三方网关或中转渠道在遇到结束标记（Stop Signature）断尾时下发的空对象数据，且缺乏原生的网络抗抖动自动重试。

### 2. 升级架构设计
我们彻底清洗了全线代码，让所有涉及大模型通信的逻辑（包含主引擎异步流式、第二层同步安全审查、第三层后台记忆蒸馏）**100% 统一收拢到官方 OpenAI Python SDK 下**：
- **官方 AsyncOpenAI / OpenAI 客户端**：原生自带完备的指数退避重试机制，遇到网络抖动、频次超限或服务器过载全自动自愈。
- **结构化序列化对齐**：官方 Response 对象通过模型结构化拍平转换为标准原生字典，向上完全兼容既有的业务策略层，不需要改动任何外围编排逻辑。

## 生产级 Bug 故障排查与修复回顾

在系统的集成和实战调试（例如让 Agent 编写复杂的贪吃蛇代码）过程中，我们连续攻克了数个阻碍主流程闭环的灾难性 Bug。以下是问题成因与终极解法回顾：

### 1. 策略层默认构造导致的命名空间死锁
- **故障原因**：重构时文件顶部相互引入，引发了 Python 极易爆发的**循环引用（Circular Import）死锁**。
- **工业级解法**：在主引擎构造函数内部实施**局部延迟导入（Lazy Import）**，彻底拔除符号死锁，实现组件间的干净解耦。

### 2. 伪造工具返回标识引发的官方接口参数非法熔断
- **故障原因**：旧版的快速失败阻断机制在遇到拦截时直接跳出循环，并伪造了一个自定义的工具返回标识。这触犯了官方对于多工具同时调用必须一一强配对的契约。
- **工业级解法**：重构为**有状态取消机制**。遇到阻断时循环不终止，对后续被波及的工具调用，利用它们原本合法的真实请求标识返回明确的取消声明。既完美顺应了接口配对校验，又实现了无损的快速失败阻断。

### 3. 第三方网关断尾下发空对象导致的空指针流式中断
- **故障原因**：某些第三方中转代理在吐出结束标记时，会下发一个空碎片。原代码未加防护直接读取其内容属性，造成空指针崩溃。
- **工业级解法**：在流式迭代器的最前端架设点对点强制判空安全网，直接跳过此类空碎片。并配合反射刺探，确保运行期流式基座固若金汤。

### 4. 非标准乱码字符污染导致的编码序列化锁死
- **故障原因**：大模型编写的图形界面程序（如贪吃蛇游戏）由于缺乏物理显示器，在沙箱后台运行时会被系统抛出图形环境崩溃报错。终端在捕获这些非标准的中文字符乱码时，内部将其转化为了非法的**孤立代理对字符（Surrogates 编码异常）**并写入了短期历史。当下一次输入新需求时，官方库在将历史序列化进行网络传输的瞬间，触发标准协议硬拦截，导致会话永久坏死。
- **工业级解法**：在主调用引擎的最前端入口，部署高阶**递归清洗净化器**。在数据序列化前，深度向下扫描整个消息数组，将所有处于非法区间的孤立代理对字符强制洗净剔除，实现跨越乱码污染的完全自愈。
